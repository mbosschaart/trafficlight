Traffic Light API Documentation

Complete API reference for the Traffic Light Control System

← Back to Traffic Light

Base URL

http://localhost:5005

Authentication

All /api/traffic-light/* and /api/registry/* endpoints require a Bearer token when an API key is configured. Settings and debug endpoints used by the UI do not.

Authorization: Bearer {{ api_key or 'your-api-key' }}

Current API key: {{ api_key if api_key else '(empty — auth disabled)' }}

Change the key from the main page, or set the API_KEY environment variable on startup. Default key is secretapikey.

API surface

  • Control — /api/traffic-light/* (status, colors, location ID)
  • Registry — /api/registry/traffic-lights (CRUD over 1000 Dutch inventory records)
  • Settings — API key, serial number, reset, force agent check
  • Debug — live request log for the UI traffic monitor

Get Traffic Light Status

GET /api/traffic-light/status

Retrieve the current status of the traffic light.

Response

{
  "color": "red",
  "timestamp": "2024-01-15T10:30:00.123456",
  "success": true
}

Response Fields

Field Type Description
color string Current color: red, amber, green, or failure (both recoverable and persistent failure report as "failure")
timestamp string ISO 8601 timestamp of when the color was last changed
success boolean Indicates if the request was successful

Example Request

curl -X GET http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

Set Traffic Light Color

POST /api/traffic-light/status

Change the traffic light to a specific color.

Request Body

{
  "color": "red"
}

Request Fields

Field Type Required Description
color string Yes "red", "amber", "green", "failure" (recoverable), or "persistent_failure" (sets color to failure and permanently blocks further changes). Status always returns "failure" for both failure modes.

Success Response (200)

{
  "color": "red",
  "success": true,
  "message": "Traffic light set to red",
  "timestamp": "2024-01-15T10:30:00.123456"
}

Error Response (400)

{
  "success": false,
  "error": "Invalid color. Must be one of: red, amber, green, failure, persistent_failure (or 'reset' to clear persistent failure)"
}

Example Request

curl -X POST http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"color": "green"}'

# Failure mode (blinking amber)
curl -X POST http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"color": "failure"}'

# Persistent failure (blocks color changes until reset)
curl -X POST http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"color": "persistent_failure"}'

Get Valid Colors

GET /api/traffic-light/colors

Get the normal settable traffic light colors (failure modes are not included).

Response

{
  "colors": ["red", "amber", "green"],
  "success": true
}

Example Request

curl -X GET http://localhost:5005/api/traffic-light/colors \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

Get Location ID

GET /api/traffic-light/location-id

Get the traffic light location ID (10-digit serial number). Change it from the main page UI.

Response

{
  "location_id": "4829173056",
  "serial_number": "4829173056",
  "success": true
}

Example Request

curl -X GET http://localhost:5005/api/traffic-light/location-id \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

Traffic Light Registry (CRUD)

SQLite inventory of 1000 traffic lights across Dutch cities. The default serial 4829173056 is located in Utrecht. Bearer auth required when an API key is set.

GET /api/registry/traffic-lights

List lights. Query params: limit, offset, city, q, or all=true for the full database in one response.

curl -X GET "http://localhost:5005/api/registry/traffic-lights?city=Utrecht&limit=5" \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

# Entire database (all 1000 records)
curl -X GET "http://localhost:5005/api/registry/traffic-lights?all=true" \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"
GET /api/registry/traffic-lights/<serial_number> 
curl -X GET http://localhost:5005/api/registry/traffic-lights/4829173056 \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"
POST /api/registry/traffic-lights 
curl -X POST http://localhost:5005/api/registry/traffic-lights \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{
  "serial_number": "9999999999",
  "city": "Utrecht",
  "address": "Domplein 1, 3512 JC Utrecht",
  "latitude": 52.0907,
  "longitude": 5.1214,
  "operational_since": "2018-03-12"
}'
PUT /api/registry/traffic-lights/<serial_number>

Partial updates allowed.

curl -X PUT http://localhost:5005/api/registry/traffic-lights/9999999999 \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"address": "Domplein 2, 3512 JC Utrecht"}'
DELETE /api/registry/traffic-lights/<serial_number> 
curl -X DELETE http://localhost:5005/api/registry/traffic-lights/9999999999 \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

Settings & Agent

Used by the web UI. Bearer auth is not required for these routes.

PUT /api/settings/api-key 
curl -X PUT http://localhost:5005/api/settings/api-key \
  -H "Content-Type: application/json" \
  -d '{"api_key": "secretapikey"}'
PUT /api/settings/serial-number

Body: {"serial_number":"4829173056"} (exactly 10 digits). Returned by GET /api/traffic-light/location-id.

curl -X PUT http://localhost:5005/api/settings/serial-number \
  -H "Content-Type: application/json" \
  -d '{"serial_number": "4829173056"}'
POST /api/settings/force-agent-check

Sends "Inspect the light" to the local OpenAI-compatible agent (AGENT_BASE_URL, default host port 5050). Returns the agent reply in message.

curl -X POST http://localhost:5005/api/settings/force-agent-check
POST /api/settings/reset

Resets light to red, clears the request log, restores default API key and serial number.

GET DELETE /api/debug/requests

Live API traffic monitor ring buffer (max 100 entries). Optional query: ?since=<seq>.

HTTP Status Codes

Code Description
200 OK - Request successful
400 Bad Request - Invalid input data
401 Unauthorized - Missing or invalid Bearer API key
500 Internal Server Error - Server-side error

Testing the API

You can test the API using curl, Postman, or any HTTP client. Here are some examples:

Test Sequence

# 1. Check current status
curl -X GET http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

# 2. Set traffic light to green
curl -X POST http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"color": "green"}'

# 3. Verify the change
curl -X GET http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

# 4. Look up default inventory serial (Utrecht)
curl -X GET http://localhost:5005/api/registry/traffic-lights/4829173056 \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

# 5. Export entire registry
curl -X GET "http://localhost:5005/api/registry/traffic-lights?all=true" \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}"

# 6. Try setting an invalid color (should return error)
curl -X POST http://localhost:5005/api/traffic-light/status \
  -H "Authorization: Bearer {{ api_key or 'your-api-key' }}" \
  -H "Content-Type: application/json" \
  -d '{"color": "blue"}'
